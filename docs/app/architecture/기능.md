# 층 구조

어디를 고쳐야 하는지, 무엇을 건드리면 안 되는지의 기준.

---

```
화면 (screens, sheets, components)
      ↓  useStore() / useUi() / useAuth()
상태 (lib/store.tsx, lib/ui.tsx, lib/auth.tsx)
      ↓  Repository 인터페이스
저장 (lib/repo/*)  ──  로컬(IndexedDB)  +  서버(Supabase)
```

두 가지만 지키면 된다.

- **화면은 저장소를 직접 부르지 않는다.** 늘 스토어를 지난다
- **스토어는 Supabase를 모른다.** `Repository` 인터페이스만 본다

이 덕분에 2단계(로그인·동기화)를 붙일 때 **화면을 거의 손대지 않았다.**
`getRepository()`가 감싼 것을 돌려주게 바꾼 게 전부다.

## Repository 한 겹

```ts
interface Repository {
  loadAll(): Promise<Snapshot>
  saveTask / saveTasks / deleteTask / deleteTasks
  saveCategory / deleteCategory
  savePreset / deletePreset
  saveShopItem / deleteShopItems
  saveMemo / deleteMemo
  loadSettings / saveSettings
  remember / graves / forget      // 지운 것 기억하기
  clearAll()
  sync?(): Promise<Snapshot>      // 로그인했을 때만 있다
}
```

구현체 셋:

| 구현체 | 언제 |
|---|---|
| `IndexedDbRepository` | 브라우저. 진짜 저장소 |
| `MemoryRepository` | SSR·테스트. IndexedDB 없는 곳에서 앱이 안 죽게 |
| `SyncedRepository` | 로그인했을 때. 위의 로컬 것을 감싸 서버와 맞춘다 |

## 모든 쓰기는 낙관적

체크하면 화면이 먼저 바뀌고 저장은 뒤에서 조용히 간다.
`await`을 걸어 사용자를 기다리게 만들지 않는다. 실패하면 토스트로 알리고 화면은 그대로 둔다.

스토어의 `write()`가 그 통로다.

## 날짜는 문자열

앱 전체에서 `'YYYY-MM-DD'`. **`Date` 객체는 `lib/date.ts` 안에서만 산다.**

시간대 때문에 하루가 밀리는 사고를 원천에서 막는다.

## 상태 셋

| 어디 | 무엇 |
|---|---|
| `store.tsx` | 데이터 전부와 쓰기 동작 |
| `ui.tsx` | 지금 보는 탭·날짜·필터·열린 시트 (저장하지 않는다) |
| `auth.tsx` | 세션. 제일 바깥에 있어서 스토어가 계정을 알 수 있다 |
