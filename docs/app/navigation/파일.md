## 밀고 들어가기 — 스택

```ts
pushView({ kind: 'settings' })            // 한 겹 쌓는다
pushView({ kind: 'room', id: room.id })   // 딸린 값이 있으면 같이
popView()                                 // 한 겹 벗는다
replaceView({ kind: 'room', id })         // 이 겹을 갈아끼운다
setTab('day')                             // 탭을 옮긴다. 쌓인 건 다 벗는다
```

`view`는 **스택 맨 위에서 나온다.** 쌓인 게 없으면 보던 탭이다.
그래서 `view === 'shop'` 같은 검사가 그대로 산다.

딸린 값이 필요하면 `route`를 본다.

```ts
const { view, route, depth } = useUi();
if (route?.kind === 'room') route.id;
const pushed = depth > 0;   // 탭바·+ 버튼을 내릴지
```

## 시트는 넷뿐이다

`task` · `preset` · `shopItem` · `roomField`. **항목 하나를 손보는 자리만 남는다.**

```tsx
<Sheet title="할 일 수정" onClose={closeSheet} />
```

상위로 가는 `onBack`은 안 쓴다. 상위가 시트가 아니라 뒤에 깔린 화면이라서다.

## 조심할 것

- **`.wrap`의 아래 여백은 탭바 높이(`--bar`)를 비운 것이다.**
  탭바를 감추는 화면에서는 그만큼 빈 자리가 남는다 (지금은 그냥 둔다)
- **`PageBar`의 `-mx-4 px-4`는 `.wrap`의 좌우 여백(16px)을 뚫는 것이다.**
  헤더와 같은 수를 쓴다. 여백을 바꾸면 둘 다 고쳐야 한다
- **새 Route를 더할 때는 세 곳을 같이 고친다** — `ui.tsx`의 `Route`,
  `types.ts`의 `ViewKind`, `AppShell`의 `screenOf`. 하나만 빠지면 타입이 잡아준다
- 입력 칸을 화면 맨 위에 두면 포커스 테두리가 고정 헤더에 덮인다.
  `outline-offset: -2px`로 안쪽에 그려서 막았다
- 첫 화면·로그인 화면은 `.wrap`을 안 쓴다. 탭바가 없어서 여백 계산이 다르다
