# 기능 정리

지금까지 만든 것과, 그렇게 만든 이유.
"왜 이렇게 했는지"가 없으면 나중에 좋은 뜻으로 되돌려 놓게 된다.

---

## 1. 할 일

### 세 화면

| 탭 | 무엇 |
|---|---|
| 일 | 그날 할 일. 진행 스트립, 자주 쓰는 일 칩, 목록, 지난 미완료 |
| 월 | 달력. 칸마다 그날 할 일 제목 최대 3개, 넘치면 `+N` |
| 기록 | 자주 하는 일을 한 달치 격자로 칠한다 (습관 트래커) |

**월별을 막대 그래프로 바꾸지 않는다.** 통계가 아니라 "무슨 날에 뭘 하는지"가 보여야 한다.

### 반복 주기 — 이 앱의 핵심

**미래 회차를 미리 여러 개 만들지 않는다. 완료할 때 다음 1건만 만든다.**

다음 회차의 기준일은 **실제로 체크한 날과 그 할 일의 날짜 중 늦은 쪽**이다.

```
8일 주기, 8/4짜리를 8/9에 완료  →  다음은 8/17  (8/12가 아니다)
```

완료일만 기준으로 잡으면 미리 체크했을 때 같은 날 두 건이 생긴다. 프로토타입에서 실제로 터졌던 버그라 테스트로 묶어뒀다 (`src/lib/repeat.test.ts`).

- 이미 그 항목을 부모로 하는 미완료 회차가 있으면 만들지 않는다 (중복 방지)
- **완료 취소** → 그 항목이 낳은 미완료 회차를 거둔다. "안 한 걸로 하자"는 뜻이니까
- **삭제** → 그 한 건만 지운다. 다음 회차는 남는다. 기록을 지운 것이지 반복을 그만둔 게 아니다
- 종료일(`repeatUntil`)이 지나면 더 만들지 않고 "반복이 끝났습니다"를 알린다

### 미루기

- 미완료 목록 아래 **`남은 N개 내일로 미루기`** — 하루를 닫는 동작. 옆 달력으로 날짜 지정
- 줄마다 화살표로 **한 건씩**. 오늘 지나면 안 해도 되는 일이 있으니까
- 수정 시트에 `오늘 / 내일 / 다음 주` 칩 (고칠 때만 보인다)

날짜만 옮기고 `cycleSince`는 그대로 둔다. 기준일 규칙 덕분에 **미뤄도 주기가 틀어지지 않는다** — 8/4를 8/5로 미뤄 8/5에 해도, 안 미루고 8/5에 해도 다음은 똑같이 8/13이다.

**자동 이월은 넣지 않았다.** 항목이 저절로 옮겨 다니면 기록 격자의 지난 칸이 비어서, 그 날 하기로 했었다는 사실 자체가 사라진다. 내가 눌러서 옮기는 것과는 다르다.

### 카테고리

- 처음엔 `집안일`, `건강` 둘뿐. 나머지는 필요할 때 만든다
- 색은 자유 입력이 아니라 팔레트 10개 중에서
- **지우면 그 안의 할 일은 남은 카테고리로 옮겨진다.** 함께 사라지지 않는다. 몇 개가 옮겨지는지 먼저 알려준다
- 헤더 아래 필터 줄. 세 화면 모두에 걸리고 자주 쓰는 일 칩까지 걸러진다
- **필터를 켜도 앱 강조색은 안 바뀐다.** 누른 칩만 자기 색을 입는다

### 자주 쓰는 일

날짜 없이 등록해두고 칩을 눌러 그날 목록에 넣는다. **기본값은 없다** — 비워두고 직접 채운다.

## 2. 장보기

**할 일과 같은 서랍에 넣지 않았다.** `우유`는 할 일이 아니다.

날짜를 붙이면 안 산 우유가 `3일 지남`으로 뜨는데 그건 밀린 일이 아니다. 그래서 날짜·주기·우선순위·카테고리가 전부 없다.

- 탭이 아니라 **헤더 장바구니 아이콘**으로 밀고 들어간다. 메인은 할 일이니까. 담아둔 개수는 배지로 알린다
- 위에 입력 줄이 늘 떠 있고 **엔터로 이어 적는다**. 시트를 띄우면 다섯 개 적을 때 다섯 번 열어야 한다
- 이름을 누르면 **이름 / 어디서 / 메모** 시트. 구입처는 전에 적은 곳이 자동완성으로 뜬다

### 목록과 기록이 갈리는 규칙 — 딱 하나

> 오늘 담은 것까지는 목록에 남고, 그 전에 담은 것은 다음 날 저절로 기록으로 내려간다.

마트에서 "이거 담았나" 확인은 되면서 누를 것은 없다. 치우는 버튼을 없앤 이유다. 보관 상태를 따로 저장하지 않고 `boughtOn` 날짜 하나로 판단하니 어긋날 것도 없다.

- 맨 아래 **`지난 장보기`** — 날짜별로 묶어서. 눌러 다시 담으면 기록은 그대로 두고 새 줄이 생긴다
- **두 번 이상 산 것은 자주 사는 것 칩**으로 자동으로 올라온다. 다시 담을 때 메모·구입처도 딸려온다

## 3. 메모

**대화창이 아니라 종이 뭉치다.** 카톡이 불편한 건 대화가 안 돼서가 아니라 위로 흘러가버려서다. 계좌번호·관리비처럼 한 번 적어두고 계속 보는 것들 자리.

- 헤더 메모 아이콘으로 들어간다
- **제목 칸이 없다.** 접었을 때 첫 줄이 제목 노릇을 한다. 적을 때마다 제목부터 지어내야 하면 손이 무거워진다
- 한 번에 한 장만 펼쳐진다. `새 메모`를 누르면 쓰던 건 접히고 빈 칸이 올라온다
- **빈 채로 접힌 메모는 버린다.** 빈 카드가 쌓이지 않게
- 저장 버튼이 없다. 적는 대로 저장된다
- 두 장 넘으면 돋보기로 찾기

**안 본 표시** — 마지막으로 본 뒤에 고쳐진 메모가 있으면 아이콘에 점이 뜬다. 혼자 쓰는 동안에는 거의 안 뜬다. 상대가 적어둔 걸 알아채는 자리다.

## 4. 계정과 동기화

### 로그인

**로그인해야 들어온다.** 첫날부터 백업되고, 나중에 합칠 일이 안 생긴다.

- 본인은 **이메일 + 비밀번호**
- 초대 링크(`?join=코드`)로 온 사람은 **이름 한 칸**만. 뒤에서 익명 로그인이 돌지만 본인에겐 안 보인다. 가입을 시키려다 앱이 죽는 지점이 대부분 여기다
- 비밀번호 찾기 — 메일 링크로 돌아오면 새 비밀번호를 정하기 전까지 그 화면에 머문다
- 설정 → 계정에서 로그아웃

**열쇠(`NEXT_PUBLIC_SUPABASE_*`)가 없으면 로그인 자체를 걸지 않는다.** 접속할 곳을 모르는 채로 벽만 세우면 로그인은 전부 실패하는데 할 일 목록에는 영영 못 들어간다.

### 동기화

화면은 **늘 로컬(IndexedDB)만 본다.** 체크하면 즉시 반응하고 지하철에서도 열린다. 서버로 보내는 일은 뒤에서 하고, 실패해도 화면은 멀쩡하다.

맞추는 규칙:

- 양쪽에 있으면 **`updatedAt`이 늦은 쪽이 이긴다.** 목록을 통째로 덮지 않는다 — 상대가 방금 체크한 게 사라지면 안 된다
- 서버에만 있으면 받아온다
- 로컬에만 있는데 **지난 동기화 뒤에 고쳤으면** 아직 안 올린 것 → 올린다
- 로컬에만 있는데 **그전 것이면** 남이 지운 것 → 여기서도 지운다

못 보낸 것은 다음 동기화가 주워간다. `syncedAt`이 성공했을 때만 앞으로 가기 때문이다.

**지우기는 진짜로 지우지 않는다.** 서버에는 `deleted_at`을 달고, 로컬에는 무덤(`graveyard`)에 적어뒀다가 서버에 알린 뒤 잊는다. 안 그러면 지운 게 다음 동기화에 되살아난다.

두 가지 안전장치:

- **같은 기기에 다른 사람이 로그인하면** 로컬을 비우고 시작한다. 저장소는 계정별이 아니라 브라우저별이라, 앞사람 목록이 뒷사람 계정으로 올라갈 수 있다
- **기본 카테고리는 맞춘 뒤에 심는다.** 먼저 심으면 기기마다 만들어서 `집안일`이 두 벌이 된다. 이미 양쪽에 생긴 경우엔 이름이 같은 것끼리 서버 쪽으로 몰아준다

## 5. 껍데기

- **PWA** — 홈 화면 설치, 오프라인 열기. 아이콘은 `npm run icons`로 뽑는다 (마스커블 포함)
- **첫 화면** — 처음 한 번만. `시작하기`를 누르면 다시 안 나온다
- 시트는 한 번에 하나. 나가는 길은 **위 왼쪽 화살표 하나** (아래에 닫기 버튼을 또 두지 않는다)
- 가로로 넘치는 칩 줄은 끝을 흐려서 더 있다고 알린다
- iOS 노치·홈 인디케이터 대응 (`env(safe-area-inset-*)`)

## 아직 안 한 것

- **방과 초대 링크** — DB 쪽(`create_room`, `join_room`)은 다 돼 있고 화면·연결이 없다. 지금은 각자 자기 목록만 본다
- **완료자 이름 배지** — `doneBy` 자리는 뚫어놨지만 늘 `null`
- **실시간** — 앱 열 때 한 번만 맞춘다. 켜둔 채로 상대가 바꾸면 바로 안 넘어온다
- **알림(3단계)** — 아침에 오늘 할 일 한 줄. 서버 cron이 필요하다
- 삭제 되돌리기 — 할 일 줄의 `×`는 확인 없이 바로 지운다
- 내보내기, 홈 화면 위젯
