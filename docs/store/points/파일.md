# 포인트 — 파일

| 파일 | 하는 일 |
|---|---|
| `supabase/schema.sql` | ★ `point_log` · `stamp_points()` · `my_points()` · `tasks.done_by_id` |
| `sql/2026-08-25_곰돌이-포인트-상점.sql` | 이미 도는 DB에 얹는 같은 것 |
| `src/lib/costumes.ts` | `PER_TASK` · `DAILY_CAP` · `WEEK_STEPS` — **화면에 적는 점수표** |
| `src/lib/repo/remote.ts` | `pullGomdori()` — `my_points()`를 부르는 자리 |
| `src/lib/gomdori.tsx` | `GomdoriProvider` — 잔액을 들고 있는 자리 |
| `src/screens/store/Coin.tsx` | 동전 표 |

앱에는 **포인트만 보는 화면이 없다.** 잔액은 [상점](../items/기능.md) 제목 줄에 선다 —
가격을 보면서 고르는 화면이라 위로 올라가 확인하게 만들면 안 된다.

## 값이 흐르는 길

```
할 일 체크  → tasks.done · done_on · done_by_id      ← 여기까진 그냥 할 일이다

앱이 잔액을 물음
  → my_points()
       ├ stamp_points()        ← 안 준 것부터 채운다. 앱은 이걸 따로 못 부른다
       │    ├ 1) 할 일 하나 5P — 그 날 몫이 30을 넘지 않는 데까지
       │    ├ 2) 그 주 10·20·30개 — 넘길 때마다 한 번씩
       │    └ 3) 첫 완료 50P — ref가 'first-task' 하나뿐이라 한 번만
       └ 100 + point_log 합 − costume_owned.price 합
  → 숫자 하나
```

## 조심할 것

- **`point_log`의 열쇠가 `(user_id, kind, ref)`다.** 이 셋이 같으면 두 번 안 들어간다 —
  체크를 풀었다 다시 눌러도 마찬가지고, 그게 되돌리는 코드를 없앤 자리다
- **넣는 길은 `stamp_points()` 하나뿐이다.** `point_log`에 insert 정책을 열면
  아무 값이나 적어 넣을 수 있다
- **주는 월요일 시작이다**(`date_trunc('week')`). [앱 설정의 주 시작 요일](../../app/prefs/기능.md)을
  여기 끌어오면 설정을 바꿀 때마다 이미 준 주간 보상의 기준이 흔들린다
- **`done_by_id`로 센다.** `done_by`(표시 이름)로 세면 별명을 바꾼 순간 옛 점수가 남의 것이 된다
- **하루 상한의 순번은 `updated_at` 순이다.** 먼저 끝낸 것이 먼저 받는다
- **`costumes.ts`의 점수표는 화면에 적는 값이다.** 진짜로 얼마가 붙을지는 늘 서버가 정한다.
  둘이 어긋나면 **서버가 맞다**
- **잔액을 담아두지 않는다.** 담는 순간 체크를 풀 때 되돌리는 코드가 필요해진다
- 로컬 저장소 쪽에 짝이 없다 — **로그인한 사람만 갖는 것**이라 서버 하나뿐이다
