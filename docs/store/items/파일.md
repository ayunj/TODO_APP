## 값이 흐르는 길

```
홈 상점 띠 → pushView({kind:'store'}) → StoreScreen

앱 켜짐   → pullShop()                          ← 로그인과 상관없다
              ├ shop_group · shop_family         칩 두 층
              ├ costume_season                   세트
              └ costume_catalog                  파는 중인 것만 (RLS)
          → 못 받으면 BUILTIN이 그대로 선다

그림   → Art: img(shop 통) → builtinImg(앱) → 사라짐
              올린 것          물러설 자리      깨진 그림은 안 띄운다

화면 열림 → pullGomdori()
              ├ my_points()                     잔액
              ├ costume_owned.select            가진 것
              └ gomdori.select                  입은 것

카드 누름 → 걸쳐보기(trying)          ← 아직 안 산다. Stage에 그대로 세워본다
사기 누름 → buy_costume(key)
              ├ 값표에서 값을 찾는다   ← 앱이 보낸 값은 안 쓴다
              ├ 포즈·숨김·잔액을 막는다
              ├ costume_owned에 한 줄 (산 값을 박아서)
              └ grant_poses()          세트가 찼으면 포즈가 딸려 들어온다
          → 남은 포인트
          → refresh() → wearCostume()  ← 산 것은 바로 입힌다
```

## 조심할 것

- **값은 앱이 안 보낸다.** `buy_costume(item)`은 열쇠 하나만 받는다 —
  값을 같이 받으면 `이 옷 0원이요`를 막을 수가 없다
- **`costume_owned`에 insert 정책이 없다.** 넣는 길은 `buy_costume` 하나다.
  열면 잔액을 안 보고 그냥 넣을 수 있다
- **산 값을 박아둔다.** 값이 바뀌어도 이미 산 것은 그때 값이라야 잔액이 안 흔들린다
- **포즈는 못 산다.** 파는 물건이 아니라 세트를 다 모으면 오는 것이다
- **세트는 살 때와 잔액을 볼 때 둘 다 확인한다.** 살 때만 보면
  [숨겨뒀던 소품](../admin/기능.md)이 켜졌을 때 뭔가 하나 더 사기 전까지 못 받는다
- **`costumeOf()`는 없는 열쇠면 기본 곰돌이를 준다.** 서버에만 있고 앱에는 없는 옷이
  내려와도 화면이 비지 않는다
- **목록이 둘이다.** 값을 고칠 때는 `costumes.ts`와 `costume_catalog`를 **같이** 고친다.
  어긋나면 서버가 맞다
- **그림 없는 것은 값표에 안 둔다.** `img`도 비어 있고 앱에도 파일이 없으면
  상점에 회색 네모로 뜨는데, 그게 **파는 물건으로 읽힌다** — 걸쳐봐도 300P를 치러도
  아무것도 안 바뀐다. 그려지면 그때 넣는다 ([그릴 것](../../../design/g/그릴-것.md))
- **그림을 앱에 넣을 때는 `assets/gomdori/<열쇠>.png`에 두고 `npm run gomdori`.**
  원본 1.4MB를 `public/`에 그대로 넣으면 **홈이 뜰 때마다 1.4MB를 받는다**
- **올릴 때는 `npm run shop`.** `shop` 통은 관리자만 쓸 수 있어서 Publishable key로는
  안 된다 — Secret key를 그때만 한 줄 세워 쓴다. **`.env.local`에는 절대 안 넣는다.**
  그 파일은 `next dev`가 읽어 브라우저로 나가고, Secret key는 RLS를 통째로 무시한다
- **파일을 올리고 나서 SQL을 돌린다.** 순서가 바뀌어도 안 깨지지만(`Art`가 물러선다)
  올린 것이 진짜다
- **`img`를 비워두는 셋이 있다** — 기본 곰돌이·곰토끼·기본 룸. 로그인 전에도
  서버를 못 읽어도 서 있어야 해서 일부러 안 올린다. 채우면 그 자리에서
  Storage를 부르러 갔다가 못 부르고 빈다
- **빈 무더기·빈 대분류는 안 세운다.** 제목만 남은 격자와 눌러도 빈 화면인 칩은
  파는 것이 없는 게 아니라 **고장 난 것**으로 읽힌다
- **기본 곰돌이와 기본 룸은 안 사도 갖는다.** 서버는 `grant_free()`가, 앱은
  `FREEBIES`가 준다 — 로그인 전과 못 받아왔을 때는 앱 쪽밖에 없다
- **`itemOf()`는 절대 비어 돌려주지 않는다.** 어느 자리에 앉힐지(`kind`)를 이걸로
  정해서, 못 찾으면 방을 곰 자리에 앉히고 홈 화면에 방이 사람처럼 선다
- **`Stage`와 `RoomCard`도 상점에서 찾는다.** 박아둔 목록에서 찾으면
  나중에 올린 옷이 그 두 자리에서만 기본 곰돌이로 선다
- **빈 상점이 내려오면 안 받은 것으로 친다.** 박아둔 목록이 낫다
- **덜 찬 세트는 안 세운다.** 곰·방·소품이 다 있는 세트만 격자에 뜬다 —
  `준비 중` 칸이 뜨면 파는 물건처럼 읽힌다
- **위층 칩을 바꾸면 아래층은 `전체`로 돌아간다.** 안 그러면 없는 칩이 눌린 채로 남는다
