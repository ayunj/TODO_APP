## 표와 칸

```
costume_catalog     item_key  kind  price  season          ← 있던 것
                  + name  img  active  created_at  updated_at
                  + family_key                     어느 중분류인가

shop_group          group_key  name  ord            꾸미기 · 시즌 (못 늘린다)
shop_family         family_key  group_key  name  ord  active
costume_season    + family_key                     세트가 중분류를 정한다
shop_admins         user_id  added_at

costume_code_seq    0000001부터            next_item_code()
costume_season_seq  s000001부터            next_season_code()
shop_folder(코드)   deco/daily/gomdori     그림 둘 자리
catalog_family      트리거                  시즌 물건의 중분류를 세트에서 끌어온다
season_family       트리거                  세트의 중분류는 시즌 밑에서만
costume_catalog_season_fk                  없는 세트를 가리키면 막는다
storage:shop        <대분류>/<중분류>/<종류>/<코드>.png
```

## 층

```
대분류   꾸미기 ─ 일상 · 코스튬 · (룸, 꺼둠)          ← 중분류
        시즌  ─ 계절 ─ 봄꽃 세트 · 물놀이 세트 …     ← 중분류 ─ 세트
              └ 기념일 ─ 할로윈 세트 · 크리스마스 세트

방 · 내 옷장은 층이 아니라 가로지르는 버튼이다
```

## 조심할 것

- **`is_shop_admin()`은 `security definer`다.** 정책 안에서 `shop_admins`를 그냥 읽으면
  그 표의 정책이 다시 불린다 — `is_member`와 같은 까닭이다
- **씨앗은 `do nothing`에 가깝다.** 부딪히면 이름이 빈 줄만 채워 켠다.
  `do update`로 되돌리면 관리자가 고쳐놓은 가격이 `schema.sql`을 돌릴 때마다 날아간다
- **`active` 기본값이 `false`다.** 관리자가 넣은 줄은 숨김으로 들어온다.
  `schema.sql`이 새로 심는 것도 마찬가지다 — 그림이 없는 채로 상점에 뜨면 안 된다
- **`family_key`도 한 번만 정해준다**(`where family_key is null`). 덮으면 관리자가
  옮겨둔 중분류가 `schema.sql`을 돌릴 때마다 되돌아간다
- **번호표 권한을 안 열면 관리자도 못 넣는다.** `grant usage on sequence costume_code_seq
  to authenticated` — RLS가 아니라 권한에서 막혀서 화면에는 까닭 모를 오류로 뜬다
- **중분류 열쇠는 폴더 이름이다.** `[a-z][a-z0-9-]{1,23}` 말고는 안 받는다 —
  한글이나 슬래시가 들어가면 Storage 경로가 깨진다
- **끈 중분류도 앱에서 읽힌다.** 감추면 그 안에 든 물건이 어디 것인지 앱이 모르게 된다 —
  칩에서 뺄지는 앱이 정한다
- **세트 중분류는 시즌 밑에서만.** 꾸미기 밑 것을 달면 그 세트의 물건이
  트리거를 타고 꾸미기로 끌려가 시즌 칩에서 사라진다
- **세트 번호표도 열어야 한다**(`costume_season_seq`). 물건 것과 따로다
- **세트와 중분류는 못 지운다.** 가리키는 것이 남아 있어서다 —
  세트는 이름을 고치고, 중분류는 `active`를 끈다
- **`buy_costume`도 `active`를 본다.** 상점에 안 떠도 열쇠만 알면 부를 수 있는 자리다
- **`grant_poses`는 소품 아닌 것이 하나라도 있는 시즌만 연다.**
  이 줄이 없으면 소품만 올려둔 새 세트가 `다 모았다`로 읽혀 모두에게 들어간다
- **숨김이 된 곰·방도 세트 조건에 그대로 센다.** 빼면 하나 숨기는 순간 세트가 거저 열린다
- **`my_points()`가 `grant_poses()`도 부른다.** 살 때만 보면 숨겼던 소품을 켠 뒤
  뭔가 하나 더 사기 전까지 안 온다
- **Storage 블록은 막혀도 안 멈춘다.** 우리 표가 아니라 Supabase 것이라 권한이
  모자랄 수 있어서, `insufficient_privilege`면 `notice`만 남기고 넘어간다.
  그때는 대시보드에서 통을 손으로 만든다(public)
- **파일 이름은 코드 그대로다**(`shop/<코드>.png`). 다르게 두면 대조표가 하나 더 생긴다

## 돌리는 법

빈 DB면 `supabase/schema.sql` 하나, 이미 도는 DB면
`sql/2026-08-25_곰돌이-포인트-상점.sql` 하나. 둘 다 두 번 돌려도 된다.
자세한 것은 [database](../../account/database/기능.md).

돌린 뒤 **관리자를 손으로 하나 넣어야** 채울 수 있다.
