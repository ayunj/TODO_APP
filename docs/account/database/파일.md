# 데이터베이스 — 파일

| 파일 | 하는 일 |
|---|---|
| `supabase/schema.sql` | ★ 테이블 · RLS · `is_member` · `create_room` · `join_room` · publication |
| `src/lib/repo/remote.ts` | 로컬 ↔ 서버 모양 변환, `pull` `push` `drop` |
| `src/lib/supabase.ts` | 클라이언트 |
| `.env.example` | 열쇠 견본 |

## 이름 바꿔 끼우기

로컬은 카멜케이스, Postgres는 스네이크케이스라 `remote.ts`에서만 바꾼다.

| 로컬 | 서버 |
|---|---|
| `categoryId` | `category_id` |
| `repeatDays` `repeatUntil` `cycleSince` | `repeat_days` `repeat_until` `cycle_since` |
| `doneOn` `doneBy` | `done_on` `done_by` |
| `boughtOn` | `bought_on` |
| `order` | `sort_order` |
| `shopping`(종류 이름) | `shop_items`(테이블 이름) |

## 열쇠

| 이름 | 무엇 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 프로젝트 주소. **뒤의 `/rest/v1/`은 빼야 한다** |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Publishable key (`sb_publishable_...`) |

브라우저에 노출되는 값이라 저장소에 둬도 되지만, 프로젝트를 갈아끼울 수 있게 환경변수로 뺐다.
**Secret key(`sb_secret_...`)는 절대 넣지 않는다** — RLS를 통째로 무시한다.

배포본에도 켜려면 **Vercel → Settings → Environment Variables**에 같은 값을 넣고
**다시 배포**해야 한다. `NEXT_PUBLIC_`은 빌드할 때 코드에 박히기 때문이다.

## 조심할 것

- SQL을 고치면 **두 번 돌려도 되게** 쓴다 (`drop policy if exists` 먼저)
- 새 테이블에는 `updated_at` `deleted_at`을 반드시 넣고 RLS를 켠다
- `delete` 정책은 만들지 않는다
