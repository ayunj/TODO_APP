# 데이터베이스

Supabase(Postgres). [supabase/schema.sql](../../../supabase/schema.sql)을 대시보드 SQL Editor에
통째로 붙여넣고 한 번 실행하면 된다. 두 번 돌려도 되게 써뒀다.

**이미 돌아가고 있는 DB에는** 그 파일이 아니라 [sql/](../../../sql/README.md)에 있는 것을
날짜 순서대로 얹는다. 표를 지우고 다시 만들 수 없어서 길이 둘이다.

---

## 테이블

| 테이블 | 무엇 |
|---|---|
| `rooms` | 방. `join_code`가 초대 링크에 실린다 |
| `room_members` | 누가 어느 방에. 표시 이름도 여기 |
| `categories` `tasks` `presets` `shop_items` `memos` | 데이터 |
| `nudges` `device_tokens` | 콕 찌르기와 푸시 ([nudge](../../nudge/기능.md)) |
| `point_log` | 준 포인트 한 줄씩 ([points](../../store/points/기능.md)) |
| `costume_catalog` `costume_season` | 파는 것과 시즌 세트 ([items](../../store/items/기능.md)) |
| `shop_group` `shop_family` | 상점 칩 두 층 — 대분류와 중분류 |
| `costume_owned` `gomdori` | 가진 것과 지금 입은 것 |
| `shop_admins` | 상점을 채우는 사람 ([admin](../../store/admin/기능.md)) |

**상점 쪽 표들은 위 규칙을 안 따른다.** `room_id`도 `deleted_at`도 없다 —
방과 나누는 것이 아니라 **계정 하나에 붙는 것**이고, 지우는 일이 없다.

**로그인 계정 테이블은 만들지 않는다.** Supabase가 `auth.users`에 알아서 넣고,
우리 테이블은 참조만 한다.

모든 데이터 테이블에 있는 것:

- `room_id`가 있으면 방 것, 없으면 `owner_id` 개인 것
- `updated_at` — 합칠 때 늦은 쪽이 이기는 기준
- `deleted_at` — **지우기는 이걸 다는 것으로만 한다**
- `deleted_by` — **사람이 지운 것과 그냥 없앤 것을 가른다** ([trash](../../trash/기능.md))

`rooms`에는 **무엇을 나누는가**가 붙어 있다 — `share_tasks` `share_shop` `share_memo`.
기본은 할 일만 켜둔다 ([rooms](../../rooms/기능.md)).

## 왜 진짜로 안 지우나

두 기기가 같이 쓰면 "지웠다"도 전해져야 한다. 진짜로 지워버리면 상대 기기에는
그 줄이 그냥 남아 있다가 **다음 동기화 때 되살아난다.**

그래서 `delete` 정책이 일부러 없다. 지우기는 `deleted_at`을 다는 `update`다.

## RLS

- **방 것**이면 그 방 사람만 (`is_member(room_id)`)
- **개인 것**이면 본인만 (`owner_id = auth.uid()`)

`is_member`는 `security definer`로 감쌌다. 정책 안에서 `room_members`를 직접 조회하면
그 테이블의 정책이 다시 불려서 무한히 돈다.

**로그인 없이 조회하면 빈 배열이 나온다.** 실제로 넣어보고 확인했다.

## security definer로 여는 것들

RLS만으로 안 되는 자리들이다. 코드를 아는 사람은 아직 그 방 사람이 아니라 **방이 안 보이고**,
방 안의 것을 통째로 옮기는 일은 여러 표를 한 번에 건드려야 한다.

전부 안에서 로그인 여부와 주인인지를 **직접 본다.**

| 함수 | 무엇 |
|---|---|
| `is_member(방)` | 정책이 서로를 다시 부르는 고리를 끊는다 |
| `create_room(이름, 내이름, 색)` | 방을 만들고 나를 owner로 |
| `peek_room(코드)` | 들어가기 전 미리보기. **내용은 안 준다** |
| `is_shop_admin()` | 상점을 채우는 사람인가. `is_member`와 같은 까닭으로 감쌌다 |
| `my_points()` | 잔액. 셈하기 전에 안 준 것부터 채운다 ([points](../../store/points/기능.md)) |
| `stamp_points()` | 안 준 포인트를 채워 넣는다. **넣는 길은 이것 하나** |
| `buy_costume(열쇠)` | 산다. **값은 서버가 값표에서 찾는다** ([items](../../store/items/기능.md)) |
| `grant_poses()` | 세트가 다 차면 소품을 준다 |
| `next_item_code()` | 새 물건의 코드 — `0000001`부터 ([admin](../../store/admin/기능.md)) |
| `shop_folder(코드)` | 그 물건의 그림이 갈 자리 |
| `join_room(코드, 내이름)` | 코드가 맞으면 멤버로 넣는다 |
| `reset_join_code(방)` | 코드 새로 만들기 (주인만) |
| `share_category` · `unshare_category` | 카테고리 + 그 안 할 일·즐겨찾기를 한 번에 |
| `hand_over_room(방, 받을사람)` | 맡기고 나가기 |
| `close_room(방)` · `reclaim_room(방)` · `reclaim_my_rooms()` | 그만 나누기와 뒷수습 |
| `make_join_code()` · `tidy_code(코드)` | 여덟 자 코드 |

자세한 것은 [rooms](../../rooms/기능.md).

### join_code는 여덟 자다

처음엔 `gen_random_uuid()`에서 하이픈만 뺀 32글자였는데 **손으로 옮겨 적을 길이가 아니었다.**
헷갈리는 글자(`0 O 1 I L`)를 뺀 31자에서 여덟 개를 골라 넷씩 끊는다 — `8F3K-2QMD`.

`gen_random_bytes`는 pgcrypto가 어느 스키마에 깔렸느냐에 따라 실패해서 쓰지 않았다.

### 인자를 늘릴 때

`create or replace`로는 안 바뀐다. **Postgres는 인자가 다르면 다른 함수로 본다.**
옛것을 `drop function`으로 먼저 지워야 두 벌이 안 남는다.
`create_room`이 색 인자를 받게 되면서 한 번 걸렸다.

### room_id에는 cascade가 걸려 있다

**방을 지우면 안에 있던 할 일·카테고리가 같이 사라진다.**
그래서 `close_room`은 `reclaim_room`으로 `room_id`를 먼저 풀고 나서 방을 지운다.

## 실시간

`tasks` `shop_items` `memos` `categories` `presets`를 publication에 올려뒀다.
**구독하는 코드는 아직 없다.**
