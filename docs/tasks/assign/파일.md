## 값이 흐르는 길

```
카테고리 고름 → 그 카테고리의 roomId → 그 방 사람들 → 담당자 칩
                                    ↘ 없으면 담당자 줄이 아예 안 뜬다
```

```ts
const roomId = categoryOf(value.categoryId).roomId;
const people = roomId ? membersOf(roomId) : [];
```

할 일의 `roomId`는 **카테고리가 정한다.** 저장할 때 `categoryOf(input.categoryId).roomId`를
넣는다 — 담을 때 방을 안 묻는다는 규칙이 여기 걸려 있다.

## 회차를 낳을 때

```ts
spawnNext(done, membersOf(roomId).map((m) => m.userId))
```

`membersOf`는 **들어온 순서**로 정렬돼 있다. 번갈아가 그 순서를 그대로 쓴다.

`StoreProvider`가 `useRooms()`를 부를 수 있는 건 `RoomsProvider`가 그 위에 있기 때문이다
(`providers.tsx`: Auth → Rooms → Store → Ui). 순서를 바꾸면 여기가 깨진다.

## 조심할 것

- **`setDoneBy`는 `doneOn`을 안 건드린다.** 한 날이 바뀌면 반복 계산이 통째로 흔들린다
- **`assigneeId`로 담고 이름은 그릴 때 찾는다.** 이름을 담으면 별명을 바꿨을 때 과거가 깨진다
- **`doneBy`는 반대로 이름을 담는다.** 방을 나간 사람이 한 것도 이름은 남아야 한다
- **`assignedAt`은 `updatedAt`과 따로 센다.** 담당자가 바뀔 때만 민다 —
  제목만 고쳐도 밀면 이미 내 차례인 일로 띠가 다시 뜬다
- **`assignedBy`가 나면 띠가 안 뜬다.** 내가 나에게 준 것까지 알리면 앱이 헛말을 한다
- 사람 줄의 왼쪽 여백은 **고른 칩의 `offsetLeft`를 재서** 잡는다.
  칩 이름이 길어지면 자리도 따라 움직인다
- **사람 줄과 카테고리 줄은 같은 `ScrollRow` 안에 있어야 한다.**
  따로 두면 옆으로 밀 때 아래 줄만 제자리에 남는다
- `filter`를 바꾸면 `who`가 저절로 풀린다. `setFilter` 안에서 같이 처리한다 —
  방마다 사람이 달라서 그대로 두면 없는 사람으로 거르게 된다
