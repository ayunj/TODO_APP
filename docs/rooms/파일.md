## rooms는 이 기기에 안 담는다

할 일·장보기·메모와 달리 **방 상태는 IndexedDB에 없다.** 서버에만 있고 화면이 필요할 때
Supabase를 바로 부른다. 로그아웃하면 비운다.

방은 로그인해야 쓰는 것이라 오프라인으로 볼 일이 없고, 담아두면 "나갔는데 아직 남아 있는 방"
같은 상태를 또 맞춰야 한다.

```ts
const { enabled, rooms, membersOf, myNameIn } = useRooms();
// enabled = Supabase 열쇠가 있고 + 로그인했다
```

## 서버 함수 (`security definer`)

RLS만으로는 안 되는 것들이다. **아직 멤버가 아니면 그 방이 안 보이기** 때문이다.

| 함수 | 무엇 |
|---|---|
| `create_room(이름, 내이름, 색)` | 방을 만들고 나를 주인으로 넣는다 |
| `peek_room(코드)` | 들어가기 전 미리보기. **내용은 안 준다** |
| `join_room(코드, 내이름)` | 들어간다. 이미 든 방이면 이름만 새로 적는다 |
| `reset_join_code(방)` | 코드 새로 만들기 (주인만) |
| `share_category(카테고리, 방)` | 카테고리 + 그 안 할 일·즐겨찾기를 한 번에 |
| `unshare_category(카테고리)` | 도로 개인 것으로. `owner_id`도 임자에게 |
| `hand_over_room(방, 받을사람)` | 맡기고 나가기 — 주인만 바뀐다 |
| `close_room(방)` | 그만 나누기 — 거두고 나서 지운다 |
| `reclaim_room(방)` | 방 안의 것을 개인 것으로 되돌린다 (지우기 전에 부른다) |
| `reclaim_my_rooms()` | 갇힌 것 되찾기. 앱 열 때 한 번 |
| `make_join_code()` · `tidy_code(코드)` | 여덟 자 코드를 만들고 다듬는다 |

## 조심할 것

- **`create_room`처럼 인자를 늘리면 `create or replace`로 안 바뀐다.** Postgres는 인자가
  다르면 다른 함수로 본다. 옛것을 `drop function`으로 먼저 지워야 두 벌이 안 남는다
- **방을 지우기 전에 `reclaim_room()`을 부른다.** `room_id`에 `on delete cascade`가 걸려
  있어서 그냥 지우면 안에 있던 할 일까지 사라진다
- **서버에서 여러 줄이 한꺼번에 바뀌는 일 뒤에는 `resync()`를 부른다.** 이 기기가 고친 게
  아니라 화면을 먼저 바꿔둘 수가 없다. `share_category` 같은 것들이 그렇다
- **RPC에서 `updated_at`을 같이 민다.** 안 밀면 다음 동기화가 그 줄을 안 주워간다
- `normalizeCode`는 **대문자로** 맞춘다. 여덟 자 코드가 대문자로 담기기 때문이다
- 방을 갈아탈 때 적던 이름이 남지 않게 `RoomScreen`에 `key`를 갈라뒀다
